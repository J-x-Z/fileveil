# FileVeil 0.3 多轮审计记录

审计日期为 2026-11-12。代码基线为 `d1ceeaa`，主要修复提交为 `664557f` 与 `c5c2be6`，后续交叉复核另补当前计划资格及队列错误展示。本轮覆盖授权边界、文件重写、检测判定、资源消耗和 GUI 批量工作流。项目继续使用 MPL-2.0，第三方文件保留原有许可。

## 三轮审查

1. 第一轮独立检查 MCP、媒体与 Office 重写、水印和来源解析、GUI 报告生命周期。通过实际目录授权、合成容器和文档、固定图片与 Markdown 输入复现问题，保存修复前证据。
2. 第二轮实施局部修复并添加回归，检查原件身份、哈希、输出复验和报告状态。媒体通过原生解码器复核，Office 通过独立 ZIP/XML 和 python-docx 检查，水印数值通过 OpenCV 与 PyWavelets 对照。
3. 第三轮交叉审查改动，补查文件替换、极端预算、历史格式属性、数值临界点、报告内存与搜索分配。执行工作区测试、Clippy 和最终 release worker 性能复测。

## 已修复问题

### MCP 目录授权

原 Home 根目录判断可被大小写别名绕过，授权 `/Users` 等 Home 祖先也会扩大访问范围。现在以已打开目录的文件系统身份核对 Home 及其祖先，macOS 额外检查物理 Data 卷路径，Windows 复核实际长路径与敏感目录。具体工程子目录仍可授权。

这是本地配置约束绕过。修复前后测试仅检查授权配置和目录元数据。证据位于 `work/v03-audit/mcp-home-case-before.json`、`mcp-home-case-after.json`、`mcp-vnode-alias-before.json`、`mcp-home-ancestor-after.json`。MCP 目录检查与真实 stdio 入口分别通过 10 项和 1 项针对性测试。

### 原件复核与预算

Unix 文件打开增加 nonblocking，结合 no-follow 和普通文件检查，防止输入被 FIFO 替换后阻塞。原件复核改为固定 64 KiB 缓冲比较，复核文件身份、长度、内容及可读取属性。公开极端预算采用饱和计算，避免加法和像素内存估算溢出。

Lab 在读取文件前检查分组，在读取下一文件前检查剩余聚合预算，并在图像解码前检查全部样本格式、尺寸与聚合像素数。过长分组索引会在复制和排序前被拒绝。证据位于 `work/v03-audit/core-tests.log` 和 `watermark-lab-tests.log`。

### 手机媒体与 Office 重写

QuickTime 父级 `meta` 重建曾可能保留子级 XMP 等隐私记录。现在先净化子节点，再从净化后的字节重建父级。子节点查找按解析树连续范围定位，减少重复扫描无关节点。回归同时检查媒体负载、嵌套标准元数据与来源凭据保护。

Office 修订历史中的旧隐藏格式曾可能导致当前可见文本被删除。现在明确区分历史属性与当前属性，独立 XML 后置检查采用相同语义范围。证据位于 `work/v03-audit/bmff-before-fix.log`、`office-before-fix.log`、`formats-after-fix.log`、`office-independent.log`、`native-media-fidelity.log`。

### 水印判定与处理

公开 Stable Diffusion dwtDct 检测在量化临界点存在浮点路线差异。检测器升级为 `1.1.0`，保留方法标识，同时计算原精确半值、逐轴非融合运算与 FMA 三条路线。只有三者判定一致时返回对应确定状态，分歧返回 `indeterminate`，报告记录各路线匹配位数与范围。分歧结果不输出已确认载荷摘要。

OpenCV 对照覆盖 1,048,576 个随机 RGB 样本，U 分量无差异。PyWavelets 对照覆盖 1,024 个 Haar 系数，当前 arm64 FMA 路线无差异。PNG/JPEG 真实自然图片上的公开水印正反样本、量化临界值及判定分歧回归均通过。证据位于 `work/v03-audit/watermark-numeric-oracle.json`、`watermark-numeric-tests.log` 和 `watermark-lab-tests.log`。

同一次检测共享图像解码，处理后检测复用已经验证的像素。缩放、模糊、编码和验证中间缓冲在使用后释放。Lab 报告增加原始样本模型与 RGB8 转换范围，便于解释灰度和高位深样本的低位统计。

### Markdown 来源解析

大量同一行来源包装标记配合长空白前缀会触发重复前缀及行尾扫描。现在预计算合法初始注释位置，先拒绝无效上下文，再扫描后续结构。没有可移除范围时借用原始文本。合法包装、受保护上下文、可见文本字节与离线行为均有回归。证据位于 `work/v03-audit/provenance-tests.log`。

### GUI 与批量工作流

移除每帧整份报告深复制，发现项按每页 100 条呈现，搜索匹配结果缓存复用。每帧仍线性计算发现字段指纹，翻译与绘制限定为当页最多 100 条。批量队列增加只读图片水印检测，保留扫描和输出状态，错误按文件记录，超像素预算等失败原因在队列检测页以当前语言显示。Settings 增加像素、聚合档案与 Lab 资源预算。

GUI 对保留报告使用 128 MiB 估算堆内存阈值及 100,000 条发现阈值。完成当前任务后，达到阈值会暂停后续任务并保留已有结果。估算覆盖 JSON 数组、字符串和预览数据。证据位于 `work/v03-audit/gui-large-report.log`、`gui-batch-tests.log` 和 `workspace-tests.log`。

使用 macOS arm64 的 `/usr/bin/time -l` 直接测量 `target/release/fileveil --worker`，峰值 RSS 属于处理 worker。图片固定为 2816 × 2816，共 7,929,856 像素，SHA-256 为 `fabf4d48c2158caf73ccc38b358ee837f4b63cca2226bac911e87d081157d1bc`。Markdown 输入为 3,089,000 字节，含长空白前缀和 1,000 个同一行候选包装。

## 保留限制

- 媒体重写及独立内容摘要仍有整文件复制路径。约 8 MP Signal 处理的峰值 RSS 仍约为 357 MiB，大文件需结合设备内存设置预算。
- 当前约束覆盖文件字节、像素、聚合解压、报告估算、超时与进程树回收。操作系统级 RSS、CPU 硬配额和完整通用沙箱尚未实现，GUI 报告阈值也会包含当前任务完成后的增量。
- 公开具名水印检测及其复检有明确方法范围。未知 OEM、水印私有密钥、设备指纹归因和受限官方检测接口仍需真实样本与可用检测能力，统计异常保留为研究证据。
- 复杂 Office 语义、签名和加密输入继续采用对应保护或部分验证状态。独立解析与解码覆盖已有样本，真实应用显示保真度仍受样本覆盖范围约束。
- 固定 C2PA 依赖仍包含 `rsa 0.9.10` 的 `RUSTSEC-2023-0071`。现有例外仅依据生产路径使用公钥验签、凭据删除且没有 RSA 私钥操作。四条依赖维护状态提示仍有记录，详情见 `docs/SECURITY.md`。本轮依赖检查保存在 `work/v03-audit/dependency-audit.log`。
- 本记录的直接 worker 性能与原生独立验证来自 macOS。本地测试中的 Windows 专用条件分支及 Linux 原生交互需结合对应平台的运行记录验收。
